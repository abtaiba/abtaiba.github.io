Causal Models of Proofs

Using actual causality to explain verified Dafny programs: Hoare derivations become causal models, whose structural equations generate weighted explanations.

Overview

Based on actual causality, we designed a representation of programs that could help explain verified Dafny programs to end users. A parser breaks the program down into a causal graph, structural equations are extracted from that graph, and the equations are used to generate explanations.

Any part of a program, or the fact that the program is correct, has many possible explanations. To choose from this space of explanations we introduce a weighting mechanism; when competing explanations have the same weight, we output both.

Actual causality in context

The basic object is the Hoare derivation: the preconditions, postconditions, all intermediate verification conditions, and annotations. Decomposing it into a causal model lets us understand the flow of information, the logical structure of the proof, and whether projected changes to a program are feasible, without making those changes at runtime.

With this goal, we examine the definitions of actual cause, sufficient cause, strict sufficient cause and explanation, and establish what each means for the causal model obtained from a Hoare derivation.

From Hoare triples to structural equations

A Hoare logic judgment has the form {P} c {Q}, where P is the precondition, c the command or program, and Q the postcondition. Motivated by the definition of a Hoare triple, we translate it into the structural equation

UQ := UP ∧ Uc

where UP and Uc may be exogenous, depending on context, and UQ is endogenous, since its value is derived from them. We decompose programs in Hoare logic following this formula, using the toy language IMP to show how each rule decomposes into a causal model.

Causal model

A causal model consists of a signature and a set of structural equations. The signature is the union of a set of exogenous and a set of endogenous variables. Exogenous variables take their values from outside the model and depend on no other variables; here, they are the variables that provide the initial values of the program's variables. Every variable in the program has an associated variable in the causal model.

Actual cause

X⃗ = x⃗ is an actual cause of φ in the causal setting (M, u⃗) if all three conditions hold:

  • AC1 (M, u⃗) ⊨ X⃗ = x⃗ and (M, u⃗) ⊨ φ: the cause and the effect both actually happen.
  • AC2 There is a set W⃗ of variables in 𝒱 and a setting x⃗′ of X⃗ such that if (M, u⃗) ⊨ W⃗ = w⃗*, then (M, u⃗) ⊨ [X⃗ ← x⃗′, W⃗ ← w⃗*] ¬φ: holding W⃗ at its actual values, changing X⃗ makes φ false.
  • AC3 X⃗ = x⃗ is minimal.

As an example, consider a Hoare derivation using the sequencing rule:

{P1} c1 {P2}{P2} c2 {Q2}
{P1} c1 ; c2 {Q2}

Causal graph

The causal graph is built compositionally: there is a template causal graph for each rule application, and a program's Hoare derivation is decomposed using the template for each rule it applies.
